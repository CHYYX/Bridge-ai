Base URL

Production API surface: https://api.lanseq.cloud/v1. The interface follows OpenAI-compatible request semantics for supported endpoints.

Authentication

Approved integrations receive a dedicated bearer credential. Keep the credential server-side and send it as Authorization: Bearer $LANSEQ_API_KEY. Do not place credentials in public repositories, issues, client-side code or screenshots.

Models

The initial live model ID is qwen3.8-27b-int4, mapped to the Qwen3.8-27B family. The current served limit is 70,000 context tokens with up to 8,192 output tokens.

GET /v1/modelscurl
curl https://api.lanseq.cloud/v1/models \
  -H "Authorization: Bearer $LANSEQ_API_KEY"

Chat completions

POST /v1/chat/completionscurl
curl https://api.lanseq.cloud/v1/chat/completions \
  -H "Authorization: Bearer $LANSEQ_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "qwen3.8-27b-int4",
    "messages": [{"role":"user","content":"Return a one-line health check."}]
  }'

Streaming

Set "stream": true on supported chat-completion requests to receive server-sent events. Platform evaluators should qualify ordinary chat, streaming and tool calling with their dedicated review credential.

Data handling

Lanseq does not use customer prompts or model outputs to train models. Operational metadata may be retained for service operation, security, abuse prevention, accounting and platform obligations. Commercial integrations may have additional terms.
